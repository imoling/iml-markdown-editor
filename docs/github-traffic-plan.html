不是转化差，是只有一个渠道、而且只响了一次

拉了仓库近两周的真实流量、来源、各版本下载量和 star 的时间分布。 结论和直觉不同：愿意来的人转化得挺好，问题是没人被送过来。

前十天几乎为零，09-19 起跳、09-22 冲到 85。同一天进账 6 个 star（全部 17 个里，9 月只有 8 个，其中 6 个在这一天）。

85 个访客 → 6 个 star ≈ 7%。这个转化率在开源项目里算好的（常见 1~3%）。 所以「GitHub 流量不好」的真实含义是：只有那一天有人推了一把，其余时间没有任何入口把人送过来。

二、方案：按「投入 → 回报」排序

今天 · 半小时把放大器打开

这些不需要写代码，做完之后每一个到访者的价值都会变高。

  1. 补 Topics（GitHub topic 页是长期稳定的免费入口）： 
    markdown-editor  note-taking  notes-app  local-first  offline
ai-writing  local-llm  speech-to-text  image-generation
electron  tiptap  productivity  obsidian  chinese
  2. 传一张社交预览图（Settings → Social preview，1280×640）。 手上现成的 screenshots/本机生图.png 裁一版就行。分享到微信、即刻、V2EX、Twitter 时卡片会带图，点击率差一倍。
  3. 填 Homepage：暂时先指向 Releases 页或公众号文章，之后换成落地页。
  4. 打开 Discussions，建三个帖子：「装不上怎么办」「想要什么功能」「你在用哪个本机模型」。
  5. 老版本归档：把 v1.x 几个 Release 标成 pre-release，首屏只留 26.x。
  6. 轻量版仓库补描述和 topics，README 顶部加一行「完整版在这里 →」，主仓库也回链。两边互相导流，别各活各的。

今天修掉微信那条断路

微信里点不开 GitHub 链接。你最大的渠道，落地那一步是断的：读者看完文章，想下载，要么复制链接换浏览器，要么放弃。 09-22 那天 85 个人到了 GitHub——能想象有多少人在这一步掉了。
  • 公众号文末不要只放 GitHub 链接，放一张二维码 + 一个短链（指向 Releases 或落地页）。
  • 更狠一点：安装包同时传一份到国内网盘（123 云盘 / 蓝奏云），文章里给「网盘直下」和「GitHub（求个 star）」两个入口—— 想快的走网盘，愿意支持的去 GitHub。
  • 用不同短链区分渠道（公众号一个、V2EX 一个、小红书一个），这是唯一能绕过 referrer 被剥的办法，否则你永远不知道哪个渠道有效。

这周把「发版」变成「发一次声」

你 10 天发了 7 个版本，这是很强的势能，但每次都只在一个地方说了一句。 固定成一张清单，每次发版走一遍：

渠道怎么发预期
V2EX「分享创造」标题写功能不写产品名：「做了个 Markdown 编辑器，AI 全在本机跑，笔记不出电脑」一次 200~2000 UV，质量最高，容易来 star
小众软件 appinn投稿（网站有投稿入口），中文桌面工具最大的分发口被收录一次 = 长期搜索流量
少数派写成体验文，不写成发布公告受众和产品高度重合
即刻 / 小红书发录屏：说一句话 → 三分钟后图出现在笔记里这功能天生适合短视频，比截图强十倍
公众号已有。改进：文末加二维码 + 网盘 + 「求 star」的明确请求把现有流量的转化再抬一截

这个月打开英文世界这条线

这是回报最高但你还完全没做的一件事。你的产品定位—— 笔记本地存、AI 全在本机跑、对话/检索/转写/生图都不出网—— 正是英文圈 local-first / local-LLM 人群最买账的叙事，而那群人是会点 star 的。 现在 Google 只给你带来 2 个访客，因为仓库里没有一个英文字。
  1. 写 README.en.md（不用翻译全文，300 行压成 80 行：一句定位 + 一张 GIF + 功能表 + 下载表 + 隐私声明），顶部互相切换。
  2. 发到这几个地方（一次一个，间隔开）：
    • r/LocalLLaMA：角度是「note app that runs chat / embedding / ASR / image-gen fully local, with a memory scheduler so they don't OOM your 24GB Mac」——你的调度器那套是真有话可说的
    • r/selfhosted、r/ObsidianMD（角度：Obsidian 搬家无痛，链接语法全兼容）
    • Hacker News · Show HN：标题「Show HN: A Markdown editor where the AI never leaves your laptop」
    • Product Hunt：需要一张好图和一段 60 秒视频
  3. 提 PR 进 awesome 列表：awesome-electron、awesome-markdown-editors、awesome-selfhosted、awesome-local-llm。 被收录一条 = 一条永久的、带权重的反向链接。

这个月把首屏改成「5 秒决定要不要 star」

GitHub README 的第一屏决定一切。现在是一张静态 Mac 截图，建议换成：

  • 一张 GIF（≤ 5 MB）：空行按空格 → 输入「秋天的山间小路」→ 占位块走进度 → 图出现。 这是你最有说服力的 8 秒，静态图完全传达不了。
  • GIF 下面三行字讲清楚定位，然后立刻是下载表 —— 别让人先读一屏中文散文。
  • 补一张 Windows 截图：七成下载者是 Windows，让他们看到自己的系统。

三、发版日检查清单（复制去用）

□ 仓库：Release 标题是「用户拿到什么」，不是版本号
□ 社交预览图：这一版有新功能就换一张
□ 公众号：文章 + 二维码 + 网盘直下 + 一句「觉得有用的话给个 star」
□ V2EX 分享创造：标题写功能
□ 即刻 / 小红书：一段 15 秒录屏
□ 英文：Reddit 对口子版块（一次一个，别同一天铺）
□ 一周后：拉一次 traffic API，看哪个短链有效

怎么量（否则永远在猜）

# 每周一跑一次，存进 docs/traffic-log.md
gh api repos/imoling/iml-markdown-editor/traffic/views

gh api repos/imoling/iml-markdown-editor/releases --jq '.[0].assets[] | "\(.name) \(.download_count)"'

GitHub 的流量数据只保留 14 天，不定期抓就永久丢失。现在开始记，三个月后才有「哪个渠道有效」的答案。

四、如果只做三件事

  1. 补 Topics + 传社交预览图（半小时，永久生效）
  2. 公众号文末改成二维码 + 网盘 + 明确请求 star（下一篇就能用，直接抬高你现有唯一渠道的转化）
  3. 写英文 README，发一次 r/LocalLLaMA（一个下午，打开一条你现在完全没有的流量线）
