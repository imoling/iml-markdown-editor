## 26.5.0 — 想要的图，这台电脑自己画

写到一半想配张图，以前要么出门找素材，要么把想法发给某个在线服务。这一版起，说一句想要什么就行：**本机生图**跑在你自己的电脑上，全程离线，画完的图存在笔记旁边。

出图要几分钟，所以正文里先占一块位：上面写着提示词和进度——腾内存、读模型到百分之几、第几步、还要多久，画完原地换成真图。气泡菜单关了也没关系，占位块一直在那儿，点它就能不要了。

模型多了，一台 24 GB 的笔记本装不下它们同时跑。所以这一版还把几个本机模型的启停理了一遍：**对话与嵌入合成一组**一起启停，**转写用时自动起、用完自己退**，**生图出图时才起**；占多少内存按实测算，不够时才请人让位、让完的自己回来，对方正在干活就等它干完，而不是张口就说「内存不够」。

顺带还有：标题与列表**折叠**、转写能收**电脑放出来的声音**（macOS）、**复制为公众号格式**、日记月历按字数填深浅。

### 本机生图

- **怎么用**：空行按空格唤出 AI 气泡 → 选「AI 配图」 → 说一句想要什么 → 发送。也可以从工具栏的插图按钮进
- **两个模型可选**（「智能 → AI 配图」里选，用到才下载）：
  - **Z-Image Turbo**（约 6.7 GB，默认）：八步出图，M 系列上 768 × 768 一张约三分钟、512 × 512 约一分半，中英文提示词都认
  - **Qwen-Image 2.1**（约 10.3 GB）：更细，但同一张图要慢七倍左右
- **等的这几分钟看得见**：正文里的占位块一路报「正在腾内存 / 正在读模型 62% / 正在出图 3/8 步，还要约 40 秒 / 最后一步」，状态栏上同时写着，随时能停
- **占位块只是显示层**：画到一半保存文件，落盘的还是原文；这几分钟里你可以接着在别处写字，图会插回它原来的位置
- 图片存在笔记旁边的 `assets/` 里，正文里是相对路径；也可以继续用网络服务（Agnes、Gemini、火山引擎、MiniMax 或自定义接口）

### 几个模型，一台电脑，自己排队

「智能 → 本机资源」这一页重做了：

- **一起用的算一组**：对话模型和嵌入模型是一套文本能力，一起起、一起停、一起让位，面板上就是一行
- **转写不用你管**：录音、转写文件时自己起，一场结束自己退
- **内存按实测算**：模型跑起来之后记下它实际占了多少（按「模型 + 上下文」记），下次算预算直接用这个数。以前按文件大小推，4.4 GB 的模型开 128k 上下文实际要 8.8 GB，却只算出 6.7 GB，该拦的没拦
- **不够时才让位**：内存装得下就谁也不赶；真不够才请对话模型让个位，出完图它自己回来。想稳一点的可以打开「生图时总是先给它腾地方」
- **正在干活的会等**：要腾地方的那位正在回答问题时，先等它干完（最多 90 秒）再动它
- 面板上一眼看清账目：这台电脑的内存 = 本机模型 + 其它程序 + 现在可用

### 折叠

- 标题左边的箭头收起整节，列表项有子项时也能收；`⌥⌘[` 折叠当前小节，`⌥⌘]` 展开
- 收起来的只是不显示，文件一个字都没动；光标移进收起来的部分会自动展开

### 实时转写：电脑放出来的声音也能转

- 网课、戴着耳机开线上会议时，对方说的话以前收不到。现在「转写 → 收音设备」里可以选**系统声音**（macOS），收的是电脑放出来的声音
- 第一次用系统会请求「屏幕录制」权限；识别照样在本机完成，声音不上传
- Windows 的系统声音还在计划中

### 复制为公众号格式

- `⌘⇧P` 搜「公众号」，选个主题、看着手机预览调，一键复制，粘到公众号编辑器里就是排好的版：代码块、表格、公式、图片都带着样式过去

### 日记

- 侧边栏的月历按这一天写了多少字填深浅（像 GitHub 的提交格子），本月写了几篇写在月份旁边；点一下打开，还没有日记的日子会先问一句再新建
- **新建日记跟着你已有的目录习惯走**：平铺在 `日记/` 下、按年分、按年月分（`日记/2026/09/2026-09-23.md`）都认，不会在你整理好的目录旁边再甩一个散文件

### 修复

- 导出 PDF / HTML / 长图：代码块长行不换行、表格边框和编辑器里不一致（#2）；公式带上 KaTeX 的样式与字体；长图按正文实际高度截
- 可用内存算少了一半（只数了空闲和不活跃的部分），导致明明跑得动的出图被拦下来
- 腾内存失败时，刚被请下去的模型一直停着没人管
- 出图的「取消」真的停得下来；应用被强杀后不再留下孤儿推理进程
- 独占一行的图片不再让整篇笔记的「原样保存」失效

### 已知限制

- 本机生图目前只在 macOS（Apple Silicon）和带 Vulkan 的 Windows x64 上提供；Windows on ARM 暂无预编译运行时
- 第一次出图要先把权重读进内存，比后面几张慢
