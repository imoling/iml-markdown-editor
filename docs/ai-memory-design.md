# 可携带的 AI 记忆（设计稿）

2026-11-03，康伟提出，Claude 起草。状态：目录已按设计手工建好（`~/Personal/笔记库/记忆/`，8 篇 181 行，从 65 条 Claude 记忆、Codex 和 WorkBuddy 的偏好节归出来），编辑器功能未动；其余待定见文末四个问题。

## 要解决什么

用 Claude Code、Codex 这些工具久了，它们各自记住了你是谁、你怎么要求它干活、哪些事踩过坑。这些记忆散在每个工具自己的目录里，格式不同，互相看不见。换一个终端，一切从零开始。

目标：把这些记忆提炼成一份与工具无关的文件，放在笔记库里。新工具只要读一遍，就接得上。

Claude 的 53 条「反馈」几乎就是交互逻辑的全部：改文件前先备份、命名没定先给方案、不替用户编口号、同级项不单独换色。它们现在分散在 MBA、公众号、培训、编辑器等十几个项目目录里，只在各自目录下的会话里生效。

同名记忆跨 3 个以上项目的只有 2 条，所以靠文件名去重没用，合并要看内容。

## 哪些该带走

按用途分三层，各走各的路：

- **我是谁**。姓名、角色、场合用什么头衔、中文、机器配置。15 行以内。已在 `CLAUDE.md` 开头，搬过来后那边改成引用。
- **怎么跟我合作**。工作方式和各领域的具体规矩，就是「反馈」类记忆提炼后的样子。这是可携带记忆的主体，预计 100 到 150 行。
- **项目现状**。某个仓库或某件事的进展、决定、坑。跟着项目走，不进全局合集；笔记库 `项目/` 一事一篇的约定已经覆盖。

不带走的：参考链接按需放进对应规矩，不单列；登录凭证、会话记录、数据库一律不读；工具自己的机制（端口号、脚本路径）留在项目记忆里。

## 记忆库长什么样

放在 `~/Personal/笔记库/记忆/`，一个领域一篇，名字就是领域：

```
记忆/
  我是谁.md
  工作方式.md        # 跨领域的通用规矩
  写作.md
  公众号.md
  课件与 PPT.md
  编程.md
  投标与方案.md
```

格式取各家都能读的最小公分母：Markdown 标题加列表，不用任何工具私有的头部。一条规矩一行，括号里写日期和来源，方便回头核对：

```markdown
# 公众号

- 介绍自己的产品：背景、为什么手搓、当前功能、钩子、开源地址；不讲历史（2026-09-24，Claude / iml-markdown-editor）
- 写「为什么选 A 不选 B」之前，先查 B 是不是也能做（2026-10-09，Claude / WeChat Account）
- 命名或文案没定之前，先给方案让我拍板，再去改文章和重拍截图（2026-10-09）
```

这些笔记归用户，可以随手改。机器只往里加行，不删不改已有的行；要删由人来删。需要只给本机工具、不进导出合集的内容，在那篇笔记的开头写一行 `仅本机`。

## 四个环节

**采集**。读各工具的记忆文件。`electron/aiContext/scan.ts` 已经做了，工具表可扩展，只读表里的路径。Claude 的记忆按 `type` 直接分得出「用户」和「反馈」；Codex 取 `memory_summary.md` 的「User preferences」节；`CLAUDE.md` 的「我是谁」「工作方式」两节作为种子。

**提炼**。分两档。一档不用模型：把采到的条目按来源项目目录推断领域（MBA 归课件，WeChat Account 归公众号，imoling.git 归编程），去掉和记忆库里已有行完全相同的，剩下的作为「待加入」列出。二档要模型：把说同一件事的几条合成一条，把针对一个案例的说法泛化成规矩，这正是原方案里「重复三次就提炼」那一步。谁来跑模型见文末问题四。

**落库**。编辑器里显示待加入的行，带来源，可勾选，确认后追加到对应笔记。只追加，不覆盖。

**分发**。两条路，针对两类工具：

- 本机命令行工具（Claude Code、Codex、Gemini CLI、Hermes）：在它们的全局规则文件里写一个标记块，`<!-- iml-memory:start -->` 到 `<!-- iml-memory:end -->`，里面内联「我是谁」那 15 行，再写一句「开工先读 ~/Personal/笔记库/记忆/」。Claude Code 的 `CLAUDE.md` 支持 `@路径` 直接引入文件，可以不内联；Gemini CLI 据文档也支持，要验；Codex 不支持，只能内联加指路。只改标记块内部，改前备份，`iml-switchboard` 写 `AGENTS.md` 是先例。
- 没有文件访问的对话产品（豆包、Kimi、ChatGPT 网页、Claude 桌面版）：一键导出一份合集，顺序是我是谁、工作方式、各领域规矩，复制到剪贴板或存成文件，开新对话时贴进去。合集控制在 300 行以内，标了 `仅本机` 的不进。

Agent 自己也能取：`iml memory` 直接打印合集，`iml memory --domain 公众号` 只打一篇。换了终端，第一句话就是让它跑这一条。

## 落在产品哪里

- 「智能 → AI 上下文」弹窗加一个「记忆库」区：显示 `记忆/` 几篇、最后更新；三个按钮：从本机工具提炼、同步到各工具、导出给别的 AI。前两个点开都是先看清单再确认。
- `iml` 命令行加 `memory` 子命令，只读，和现有命令一致。写操作都留在编辑器里，必须经人确认。
- 笔记库里没有 `记忆/` 时，这一区显示一个「建立记忆库」按钮，纯记笔记的用户不受影响。

## 分期

一期：目录约定、不用模型的采集与落库、`iml memory`、导出合集。全部确定性逻辑，能写测试。

二期：同步标记块到各工具规则文件。这是原路线图里「身份同步」那一档，合并进来。

三期：模型提炼。做成一个技能，在 Claude Code 或 Codex 里跑，读 `iml memory harvest --json` 的输出，提出合并和泛化建议，用户确认后落库。编辑器本身不碰模型，记忆不出本机。接进每周复盘。

## 不做

- 不改写、不删除任何工具自己的记忆文件
- 不碰 SQLite，不读凭证和会话
- 不做记忆的实时双向同步；各工具照旧往自己的地方记，我们定期采
- 不进语义索引和「问笔记」

## 待定

1. **目录**。`笔记库/记忆/` 新建一级目录（推荐，生命周期和 `知识/` 不同，机器会往里写），还是并入 `知识/`。
2. **CLAUDE.md 怎么办**。一期就把「我是谁」「工作方式」搬进记忆库，`CLAUDE.md` 改成 `@` 引入（推荐，否则两处都是源头，会漂）；还是先只抄不动。这一步动的是你的 `~/.claude`，要你点头。
3. **分发方式**。身份内联、规矩指路（推荐，内联的东西少，不易漂）；还是全部内联到每个工具。
4. **提炼谁做**。做成技能让 Agent 自己跑（推荐，记忆不出本机，各家都能用）；还是编辑器调本机模型。
